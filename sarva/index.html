Last updated: October 4, 2026
Sarva is designed to be local-first. Your Password Store and Me Docs data is primarily stored on your Android device. Sarva does not operate a cloud database for storing the contents of these features. Google Drive is an optional backup and restore destination selected by the user.

Sarva is a privacy-focused, offline-first utility suite. The current application includes features such as Password Store and Me Docs.

2. Sarva Does Not Have a Traditional Cloud Account System

Sarva does not operate a traditional Sarva cloud account system.

Google Sign-In is used to authenticate the user for functionality involving Google services, particularly the optional Google Drive backup and restore functionality. Signing in with Google does not create a separate cloud account on a Yuddhaa-operated Sarva server.

Sarva does not operate its own authentication server and does not maintain a Yuddhaa cloud database containing users' Password Store or Me Docs contents.

3. Local-First Storage

Sarva is primarily designed to store user data locally on the Android device.

Under normal operation, your Password Store and Me Docs data is not transmitted to Yuddhaa-operated servers.

Sarva can be used without connecting a Google account or enabling Google Drive backup.

4. Password Store

Password Store allows you to store information such as usernames, passwords, descriptions, and related password-store data.

This information is stored locally on your Android device in an encrypted SQLite database using SQLCipher and AES-256 encryption.

Sarva does not upload the contents of your Password Store to a Yuddhaa-operated server as part of normal Password Store operation.

Password Store contents are not used by Yuddhaa for advertising, behavioral profiling, analytics, or AI model training.

5. Me Docs

Me Docs allows you to store documents and files locally on your Android device.

Me Docs is designed for local and offline storage. Sarva does not operate a Yuddhaa cloud storage service for your Me Docs documents.

Your documents remain on your device unless you explicitly use a feature that transfers them, such as the optional Google Drive backup functionality.

7. Google Drive Access

Google Drive integration is optional. You can use Sarva without connecting Google Drive.

Sarva currently requests the Google Drive OAuth scope:

https://www.googleapis.com/auth/drive.file

This scope is used to allow Sarva to create, upload, update, and download the Sarva backup files that the application works with.

Sarva does not request full access to the user's entire Google Drive.

When you authorize Google Drive access, Sarva creates and uses a Sarva backup folder structure in your Google Drive.

My Drive/ └── Sarva/ ├── pwdStore/ │ └── pwdStore.sarva └── meDocs/ └── meDocs.sarva

These backup files are stored in your Google Drive. Google Drive is not Sarva's primary storage and is not operated by Yuddhaa.

Google processes information relating to your Google account and Google Drive according to Google's own policies, terms, and systems.

You can review Google's documentation concerning OAuth scopes here .

8. Password Store Backup

Password Store backups are encrypted locally before being uploaded to Google Drive.

The current backup process works generally as follows:

  1. Password Store data is serialized locally on the device.
  2. An AES-256-GCM encryption key is derived using SHA-256 from the application's Password Store secret.
  3. A random 12-byte initialization vector (IV) is generated for each backup.
  4. The backup is encrypted locally using AES-256-GCM.
  5. The resulting encrypted backup is uploaded to Google Drive as a .sarva file.

Sarva does not upload the plaintext contents of the Password Store as the Google Drive backup.

Google Drive therefore receives the encrypted backup file produced by Sarva rather than the plaintext Password Store records.

9. Me Docs Backup

Me Docs backups are also encrypted locally before being uploaded to Google Drive.

During backup, Sarva collects the selected Me Docs data locally. Certain internal/system items, including profileInstalled and restore_* folders, are excluded from the backup process.

The selected data is compressed locally into a ZIP archive.

The ZIP archive is then encrypted locally using AES-256-GCM.

The resulting encrypted backup is uploaded to Google Drive as:

meDocs.sarva

The backup system does not upload the plaintext Me Docs documents as individual files to Google Drive.

10. Restore

Restore operations are initiated by the user.

10.1 Password Store Restore

When you choose to restore a Password Store backup, Sarva downloads the encrypted backup from your Google Drive.

The backup is decrypted locally on the device and the Password Store data is restored into the local encrypted SQLCipher database.

Yuddhaa does not receive the backup for server-side decryption.

10.2 Me Docs Restore

When you choose to restore a Me Docs backup, Sarva downloads the encrypted backup from Google Drive and decrypts and validates it locally.

Restored documents are placed into a new restore_* folder rather than silently overwriting existing Me Docs data.

15. Data Retention

Local Sarva data

Password Store data and Me Docs data remain on your device until you delete the relevant data using Sarva's available functionality, clear the application's storage, uninstall the application, or Android otherwise removes the application's local storage.

Yuddhaa does not maintain a separate cloud copy of this local Password Store or Me Docs data.

Google profile information

The current Google user information received during Google Sign-In is kept in application memory for the active session so that Sarva can display the signed-in account.

Sarva does not operate a separate backend that retains this profile information as a permanent user account database.

Google Drive backups

Google Drive backups are separate from local Sarva storage.

An encrypted .sarva backup remains in your Google Drive until you delete it or it is otherwise removed from your Google Drive.

Deleting local Sarva data does not automatically delete an existing backup from Google Drive.

16. Deleting Your Data

Local data

You can delete your local Sarva data using the deletion functionality available in the application.

Clearing Sarva's application storage or uninstalling the application removes its normal application-local storage according to Android's application storage behavior.

Because Sarva does not maintain a central cloud copy of Password Store or Me Docs contents, there is no Yuddhaa server database from which those local files need to be separately deleted.

Google Drive backups

Google Drive backups are separate from local Sarva data.

If you want to completely remove a backup created by Sarva, you must delete the corresponding .sarva backup from your Google Drive.

Deleting local Sarva data does not automatically delete the encrypted backup stored in Google Drive.

Google Sign-In and authorization

Sarva supports Google sign-out. Signing out clears the currently signed-in Google user from the Sarva application.

Signing out of Sarva does not delete your Google account.

If you want to completely revoke Sarva's previously granted Google authorization, you can manage or revoke the relevant authorization through your Google account's security settings.

Revoking authorization through Google may prevent Sarva from accessing Google Drive until you authorize it again.

17. Google Authentication Tokens

Google authentication and access tokens are handled by the Google Sign-In integration and are used to authenticate requests to Google services such as Google Drive.

Sarva does not operate its own authentication server and does not store Google authentication tokens on a Yuddhaa server.

This policy does not make a claim about a specific persistent local token-storage mechanism because token management is handled by the Google Sign-In integration.

18. Security

Sarva is designed around a local-first architecture that reduces the need to transmit sensitive user data to remote servers.

Security-related measures used by Sarva include:

  • Password Store data is stored in a SQLCipher-encrypted SQLite database using AES-256 encryption.
  • Password Store backups are encrypted locally using AES-256-GCM before upload.
  • Me Docs backups are compressed locally and encrypted using AES-256-GCM before upload.
  • Password Store backup encryption uses a newly generated random 12-byte IV for each backup.
  • Backup decryption takes place locally during restore.

Sarva does not intentionally upload plaintext Password Store passwords or plaintext Me Docs documents to Google Drive as part of its backup system.

No security system is completely secure. Sarva is designed to provide strong local and backup protection, but no software, encryption system, device, or electronic storage method can guarantee absolute security.

You should also protect your Android device, Google account, authentication credentials, and any secrets used with Sarva.
